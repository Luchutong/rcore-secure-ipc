## 3. 各角色实现情况

### 3.1 A：进程凭据与授权策略

已经实现：

- UID 与 Capability 组成的最小进程凭据；
- root 初始能力、降权与 fork 凭据继承；
- `getuid`、受限 `setuid`；
- 自发送、同 UID、root 和 `KILL` Capability 的信号授权判断；
- 凭据与信号授权测试程序。

当前未完成或需修正：

- `kill` 尚未统一经过 `security::preflight/complete`，无法形成完整信号审计；
- `getuid/setuid` 使用的系统调用号与冻结 API 预留的 600/601 不一致；
- 测试未加入正式 `usertests` 清单；
- 手工复核发现测试未严格判定部分子进程的超时退出，存在测试“假绿”风险；
- 分支需要同步最新 `integration` 基线并处理公共接口修改。

结论：授权功能已经形成原型，但尚未达到正式集成和完整验收条件。

### 3.2 B：用户地址与系统调用边界安全

已经实现：

- 地址加法溢出和用户虚拟地址上界检查；
- 页面映射、用户页标志及读写权限检查；
- 返回 `Option/Result` 的安全翻译和复制适配；
- `read/write/open/pipe/exec/waitpid/sigaction` 等路径的非法输入处理；
- 字符串与参数数组长度上限；
- `badptr` 恶意指针测试程序。

当前未完成或需修正：

- 多数失败路径仍返回通用 `-1`，尚未统一为 `-EFAULT` 或 `-EINVAL`；
- 跨页普通类型复制、只读页、无终止字符串、参数数组和地址对齐等边界需要补充验证；
- `badptr` 尚未加入 `make run TEST=1` 使用的正式测试清单；
- 分支包含 44 个无关的 `*:Zone.Identifier` 文件，需要在集成前清理；
- 跨角色和冻结文件修改需要通过集成审查处理。

结论：主要防护已经落地并可演示，当前处于错误语义、测试覆盖和集成规范补齐阶段。

### 3.3 C：IPC 资源与生命周期治理

已经实现：

- 每进程总文件描述符与管道端点配额；
- 管道两个端点的原子预留；
- 成功提交与失败回滚；
- `open/dup/close/pipe` 的配额记账；
- `EMFILE` 与 `ENOSPC` 错误区分；
- 管道 FD 跟踪、关闭恢复、fork 隔离和并发创建/关闭测试；
- 与 D 的管道创建和配额失败审计预集成。

当前未完成或需修正：

- 管道 `read/write` 尚未接入 `PipeRead/PipeWrite` 安全事件；
- C 分支与审计 ABI 对一次 `PipeCreate` 请求数量的解释需要在正式集成中统一；
- 对冻结门面和公共文档的修改需要通过正式集成审查；
- 可选的 `pipe2(O_CLOEXEC)` 尚未实现。

结论：资源配额与主要生命周期测试已经形成闭环，剩余工作以正式集成和管道读写审计为主。

### 3.4 D：审计、测试与持续集成

已经实现：

- 容量 256 的有界审计环形缓冲区；
- 单调事件序号、覆盖统计和 `GAP_BEFORE` 缺口标志；
- 固定 80 字节的审计记录与统计 ABI；
- 系统调用 602 `audit_read` 和 603 `ipc_stat`；
- 非破坏性游标读取、单批最多 32 条和权限/errno 映射；
- 用户态审计 API 与 `auditctl` 工具；
- 宿主测试、QEMU 审计测试、多进程压力测试和 CI 失败传播；
- C+D 预集成与 IPC 管道创建性能初测。

当前未完成或需其他模块配合：

- A+D 的真实 UID、Capability、信号成功与拒绝审计；
- B+D 的 `EFAULT`、空指针、跨页、溢出和复制失败联合测试；
- C+D 的管道读写请求量和实际字节数审计；
- A+B+C+D 的混合压力与最终性能复测；
- PR 成员审查和人工复核记录。

结论：D 的独立审计机制基本完成，剩余工作主要是跨模块联合验收。

## 5. 性能初测状态

性能程序执行 20,000 轮：

```text
pipe → close(read_fd) → close(write_fd)
```

每个版本连续运行 5 次并取中位数：

| 版本 | 中位耗时 | 中位每轮 | 审计事件增量 |
| --- | ---: | ---: | ---: |
| 原始 `main@a74354d` | 647 ms | 32,350 ns | 不适用 |
| D 未接线对照组 | 674 ms | 33,700 ns | 0 |
| C+D 安全路径 | 662 ms | 33,100 ns | 每次 20,000 |

C+D 安全路径相对原始基线的中位差异约为 2.3%。当前只能说明没有观察到数量级性能回退；该差异仍受 QEMU、程序布局和宿主调度噪声影响，不能作为最终精确开销。最终 A+B+C+D 集成后必须在相同条件下复测。
