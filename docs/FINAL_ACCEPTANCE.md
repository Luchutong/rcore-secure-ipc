## 3. 最终测试结果

```bash
cd tests/audit-host
cargo test
```

结果为 28/28 通过：

- `auditctl` 参数、分页、游标与异常数据：12/12；
- 审计系统调用权限、边界与复制失败：9/9。

### 3.2 QEMU 完整用户测试

`main` 合并后的 GitHub Actions
[运行 #34798901091](https://github.com/Luchitong/rcore-secure-ipc/actions/runs/34798901091)
在 QEMU 中执行 `make run TEST=1`，结果为：

- 预期成功用例：28/28；
- 预期失败用例：4/4；
- 总计：32/32，测试进程与 CI 均以成功状态结束。

测试覆盖正常 IPC、越权信号、无效及跨页用户地址、配额耗尽、审计读取、管道读写审计、
多进程压力以及失败后的内核存活性。

### 3.3 审计压力与内存上限

`audit_stress_test` 使用 6 个子进程，每个生成 128 个事件：

```text
children=6 events_per_child=128 total=768 retained=256 overwritten_delta=768
```

全部 768 个事件均被计数，环形缓冲区按设计只保留最新 256 条，证明审计负载不会造成
无界内存增长；覆盖统计与实际写入量一致。

### 3.4 性能复测

最终 `main@b626d92` 在 QEMU 8.2.2 中连续运行五次 `ipc_bench 20000`：

```text
778 ms, 746 ms, 737 ms, 746 ms, 727 ms
```

中位数为 746 ms，每轮约 37,300 ns，每次均记录 20,000 个成功审计事件。相对原始
`main@a74354d` 的 647 ms 中位数约增加 15.3%，属于常数级开销，没有观察到数量级性能
回退。原始数据、方法和适用边界见[性能记录](PERFORMANCE.md)。

## 5. 范围边界

本成果面向 rCore 第七章教学内核，目标是验证最小凭据、IPC 授权、安全用户访问、资源治理
和有界审计的组合设计。它不是完整 POSIX 用户管理或生产级强制访问控制系统，也不包含
SELinux、网络 IPC 和通用消息加密。上述内容属于计划外扩展，不构成本次验收缺口。
