# AI 工具使用记录

本项目按课程要求记录 AI 工具的使用情况。项目以人工开发为主体，四个安全模块的设计、实现、测试与验收均由项目成员主导完成；AI 工具仅作为辅助手段参与课题调研、代码编写、测试设计与报告整理等环节。

## 1. 使用总览

项目组使用的 AI 工具包括 **OpenAI Codex**、**DeepSeek**、**TeleAgent（星辰超级智能体）** 与 **豆包（Doubao）**，使用遵循以下原则：

1. 所有设计决策、架构选型与验收结论均由项目成员完成，AI 仅提供代码初稿或改进建议，任何 AI 产出必须经人工审阅、修改并通过运行验证后方可采纳；
2. 不把未经验证的 AI 输出直接作为实验结论，报告中的实验数据与测试结果全部来自真实运行；
3. 在提交信息、设计文档和答辩材料中标明 AI 参与部分；
4. 保留关键交互记录，说明人工修改和验证过程；
5. 不向 AI 工具提交密钥、口令或其他敏感信息。

## 2. AI 工具、使用场合与所起作用

## 3. 人与 AI 协作方式与过程

协作方式为 **“任务定义 → 人工设计 → AI 辅助实现 → 人工审阅修改 → 人工验证 → 合并入库”**：成员负责需求分析、方案设计、代码审阅与全部验证工作，AI 仅在成员明确指令下提供代码初稿、缺陷线索或文档草稿；任何 AI 产出必须经过人工修改、编译、主机测试、QEMU 用户态回归或 GitHub Actions 验证后才可合并。

典型协作过程如下：

- **模块 D 开发**（人工主导，OpenAI Codex 辅助）：成员首先完成审计 ABI 设计文档与系统调用约束，独立实现安全统计结构与系统调用框架；对其中重复性较高的结构体、系统调用封装与测试用例，使用 Codex 生成初稿后逐行审阅改写；随后由成员设计并运行 7/9/16 项主机测试及 22～23 个正常与 4 个预期异常 QEMU 用例，全部通过后合并。
- **模块 B 开发**（人工主导，DeepSeek 辅助）：成员分析 badptr 恶意输入测试暴露的 8 类缺陷，定位根因并确定修复策略，借助 DeepSeek 生成部分修复代码片段，经成员改写、补全边界检查与回归测试后集成。
- **模块 A 开发**（人工主导，TeleAgent 辅助）：于泽通完成 `Credentials` 结构与五级授权规则的设计，使用 TeleAgent 辅助生成实现初稿，人工审阅修改并补充用户态测试程序 `cred_test.rs`，内核与用户程序编译通过、QEMU 5/5 测试 PASS 后采用。
- **四模块集成**（人工主导）：组长按 B→A→C→D 依赖顺序人工完成祖先合并，处理冲突并统一用户复制、凭据授权、配额回滚与审计路径；集成测试由成员设计并运行，宿主测试 28/28、QEMU 32/32 通过，远程 CI 通过后合并至 main。
- **实验报告撰写**（人工主导，豆包辅助）：成员基于仓库代码、设计文档与测试输出撰写报告初稿，使用豆包辅助整理结构建议与文字润色，全部数据与结论经成员逐项核对，确保与真实代码和实验输出一致。

总体而言，四个安全模块的设计文档、核心算法（如审计 GAP_BEFORE 判定、配额预留与回滚、五级授权链）、全部测试用例与验收结论均由成员完成，AI 主要承担辅助编码、缺陷线索与文案整理，人工工作量占项目主体。
